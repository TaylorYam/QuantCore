# Sector-level netting rejected — keep pure-function combine

當 SR 與 SkewLS 對同一 sector 同時下單（如 SR LONG XLK + SkewLS LONG REW 形成 Tech sector 部位互抵），考慮過 [[sector-level netting]]：先 combine 兩策略的 net factor exposure，再選用單一 long ETF 或 inverse ETF 表達，少建一個對沖部位以降低 friction。Reject：7 年 backtest（2019-2026、4 alloc combos × 8 年 = 32 cells）顯示 netted 損失 0-52 bps/yr，3 個非 trivial alloc 各 cell 全敗（24/24）— 結構性問題不是 outlier 年份貢獻。Yvonne 實況 alloc (SR 0.35 / SkewLS 0.60) 虧最多 (-52 bps/yr)、Pure SkewLS 無 overlap = 0 bps (sanity check ✓ 證明兩架構 sector factor exposure 確實相同)。原因是 baseline 保留 [[inverse ETF]] 部位讓 sector 暴險在 trend 中自然 drift（XLK 漲 → XLK 部位變大；REW 跌 → REW 部位縮小 → 淨 Tech 暴險 grow），這個 leverage drift 在 2019-2026 trending market 提供 28-52 bps/yr alpha；netting 把 inverse ETF 收掉後失去這個 drift。Friction 確實省（commission tc drag 省 0.6 bps/yr、avg 1.5 positions/day 少、avg inverse-ETF % NAV 從 5.14% → 3.68%）但被 leverage drift alpha loss 完全淹沒。代價是 production 仍會在 trade log 出現重疊 sector 的兩筆單（SR XLK BUY + SkewLS REW BUY），[[daily report]] 的 P&L attribution 需手動拆 — 這是 UI/報表問題不是架構問題、後續用標籤改進即可。完整實作的成本估 ~150 行 code + 5 tests + sector mapping table 維護負擔，所以不只 benefit 為負、cost 也不低。研究腳本 `backtest/netting_research.py` 留存可重跑（`python -m backtest.netting_research --mode sweep`），若未來市場 regime 大幅轉向 reversal-heavy / choppy（如長期 sideways），可考慮重評；目前不變。
