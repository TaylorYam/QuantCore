# SP500 Constituents on-demand refresh with dense reconstruction

`refresh_constituents.py` 以 on-demand 觸發從 Wikipedia 抓 [[SP500]] [[Constituents]] + 重建 last_date 起每個交易日的 dense snapshot + yfinance backfill 新 ticker 全歷史 CSV 到 `data/stocks/`。考慮過 daily auto-fetch（reject：Wikipedia vandalism / schema 變動會 silent 污染 live trading 決策）、iShares IVV holdings（reject：增加 BlackRock CSV 依賴與 cash/T-bills filter 邏輯、邊際 benefit 小）、sparse snapshot 只寫今天那筆（reject：2015-2025 既有 Excel 是 daily-dense，降級會破壞 schema 一致性，且 backtest 在 2026+ 會跟 live drift）、event log + sidecar JSON（reject：分散 source-of-truth、需重寫 `_load_constituents()`）。代價是使用者需主動記得跑（建議週二 SP500 rebal 前）、gap > 180 天會 hard halt 要求手動處理、Wikipedia table schema 若大改需手動更新 parser。6 道 sanity gates（G1 self-consistency cross-check、G2 gap ≤ 180d、G3 changes ≤ 10 warn、G4 yfinance 存在性、G5 rename 偵測、G6 schema 驗證）取代自動 fallback — 寧可 halt 也不寫入錯資料；ctrl-C 安全靠 staging dir + atomic rename。檔名 `sp500_constituents_daily.xlsx`（去掉舊檔名 `_2015_2026` year cap）。

2026-07-05 補充：on-demand 在 live 實際發生「忘了跑」— 5 週未 refresh（快照凍在 2026-06-01），CIEN 類分類錯誤的風險無聲重演。緩解：morning check（07:00 Taipei）加入 staleness 提醒 — 快照 age > 7 天（一個週三 rebalance 週期）即發 Telegram 告警，**只提醒、不自動抓**，本 ADR 的 on-demand 決定不變（`automation/morning_check.py::constituents_staleness_warning`）。
